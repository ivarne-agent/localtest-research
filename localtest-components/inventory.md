## How the app reaches the platform

`studioctl run` sets every `PlatformSettings__Api*Endpoint` except PDF and workflow engine to
`http://local.altinn.cloud:8000/<service>/api/v1/`, which is the localtest container. Localtest's
[`ProxyMiddleware`](https://github.com/Altinn/altinn-studio/blob/447e53eb9797d4fffe63d0c61d05a1f692b4ec48/src/Runtime/localtest/src/Filters/ProxyMiddleware.cs) matches host + longest path prefix against `result.json`; no match falls through to its own
controllers (the `platform` component has an empty destination on purpose). A real container behind
`/storage` or `/authorization` therefore needs no app or app-lib change, only a topology component, a
`RuntimeBinding` and an image entry in studioctl (`studioctl-and-app-contract.md` §1.2 has the checklist).

## Vendoring practice

The monorepo root [`Makefile`](https://github.com/Altinn/altinn-studio/blob/447e53eb9797d4fffe63d0c61d05a1f692b4ec48/Makefile) already does non-squashed `git subtree pull --prefix` for app-localtest,
app-frontend-react, app-lib-dotnet, fileanalyzers, codelists and the test apps. Platform service code has
never been subtree-merged; it only arrives as NuGet contracts (`Altinn.Platform.Storage.Interface`,
`Altinn.Platform.Models`, PEP, ABAC) and as hand-ported localtest PRs.
